# 同文献证据补全

本目录用于实现：根据已有检索命中，按文章聚合材料，并在同一文献内补充人群、治疗方法、研究结果和作者结论，为后续 Qwen 综合报告提供原文及出处。

当前第 1—3 步已确认完成。第 3 步的混文属于已知上游噪声，不要求本步修复；其输出只是候选池，不是应全部纳入的补充证据。第 4 步已实现并通过程序测试，但首次真实选材出现误选、漏选，尚未达到精准补全预期；未进入第 5、6 步。此前已完成的检索、R1、R2、输入包、断言和评估模块保持原样；后续不再以原第 7—11 阶段为实施目标。

第 1 步已确认：当前文献标识可用于定位来源，但部分中文材料混有其他研究，不能把同编号下的全部文字视为同一研究；章节内编号不等于可靠的全文顺序。这些限制不会因聚合而消失。

## 文件划分

六步是实施与验证顺序，不要求一步对应一个 Python 文件。先按实际职责规划三个模块，实施时再依据真实接口确定细节，不预建空文件。

| 文件 | 职责 | 对应步骤 |
| --- | --- | --- |
| `README.md` | 保存六步计划、边界和验收依据 | 全部 |
| `models.py` | 文献任务、原文材料及选择参数、原文切片和选择结果结构 | 第 2、3、4 步 |
| `sources.py` | 从明确指定的 strict metadata 读取同文献内容，保留来源，去重并按章节内依据组织 | 第 3 步 |
| `completion.py` | 按文献聚合；保持此前实现不变 | 第 2 步 |
| `selection.py` | 构造四方向查询、保留原文坐标、批量重排、有限选择及上下文 | 第 4 步 |

第 1 步先做只读检查，不专门新增生产脚本。第 6 步使用测试和真实数据验证，不创建 `step06.py` 之类的生产模块。测试沿用仓库的 `tests/expansion/` 布局；规模增大且职责确实可以分开时再拆文件。

## 第 1 步：确认可用数据及连接方式

- 输入：既有 evidence、对应 metadata，以及当前允许使用的解析文本来源。
- 工作：检查文章编号、chunk 编号、章节与顺序字段的实际含义；选少量命中文献，验证能否取得命中之外的同文献内容。
- 输出：可用来源、真实连接字段、可用排序依据、材料覆盖范围和异常清单。
- 校验：确认取回内容属于同一文章；区分现有全文和部分解析内容；不能可靠定位时先报告，不猜测编号，不自动转向 PDF。

这一步不执行检索、不加载模型、不修改数据。现有目录和代码组织的检查，不等同于已经完成这一步。

## 第 2 步：定义最小结构并按文章聚合

- 输入：原始问题、初始证据列表、可选的已有断言结果。
- 工作：依据第 1 步确认的文章标识，将同文献的全部命中归入同一个任务，保留 evidence 编号、检索来源及断言引用。
- 输出：每篇文章一个待补全任务；同一问题下同文献只组织一次补全。
- 校验：所有初始证据均被保留；输入不被原地修改；同文献不会产生重复任务；空断言、`UNCLEAR`、`NOT_DIRECTLY_RELATED` 不导致整条证据被删除。

文章编号缺失时，先依据已确认的 metadata 查找；仍无法确认则保留原证据并说明无法补全，不凭标题相似强行合并。

### 第 2 步接口与当前验证

```python
group_evidence_by_document(

    metadata_by_chunk_id: Mapping[str, Mapping[str, Any]] | None = None,

```

函数只消费调用方传入的内存对象，不自行加载文件、模型或配置。

| 输出字段 | 含义 |
| --- | --- |
| `query_id`、`question_text` | 原问题标识和文本 |
| `document_id` | 用于查找来源的文献标识；无法确定时为 `None`，不捏造编号 |
| `evidence_packages` | 本文献的完整初始输入包副本，保留原文、全部 `query_hits`、既有上下文和警告 |
| `assertion_results` | 按 evidence 编号关联的可选断言副本，仅作辅助，不按角色筛选 |
| `input_warnings` | 问题级既有警告，以及确定性的编号恢复或缺失记录 |

- 文献任务按首次出现顺序返回，每篇内部保持初始证据顺序；这是命中顺序，不是文章原文顺序。
- 不同 evidence 命中相同 chunk 时，本步仍全部保留；chunk 去重属于第 3 步。
- 文献编号缺失时，只从调用方提供的同 chunk metadata 按 `document_id → pmcid → pmid → source_path` 恢复，沿用 R1 的来源标识规则。
- 无法恢复编号的证据逐条保留为独立任务，记录 `document_id_missing:<evidence_id>`；恢复成功记录 `document_id_recovered:<evidence_id>`，原输入包不被修改。
- 重复 evidence 编号、混入其他问题、断言编号不匹配、metadata 编号冲突、同 chunk 指向不同文献时抛 `ValueError`。
- `analysis_ready=False`、空断言、任一合法角色均不影响证据保留。断言结果由调用方按当前问题提供；未提供结果不会触发重新抽取。
- 输出中的可变列表和断言均复制，不与输入共享可变内容。

## 第 3 步：读取并整理同文献原文

- 输入：待补全文献任务、第 1 步确认的数据源及其使用边界。
- 工作：取得允许使用的同文献其他块，与初始内容合并，按 chunk 去重，并在有依据时恢复原有顺序。
- 输出：同文献可用材料集合，每段带文章编号、chunk 编号、章节信息和原文。
- 校验：没有混入其他文献；初始内容仍然存在；不静默丢弃重复 ID 下的不同文本；无依据时不假装已经恢复全文顺序。

可靠顺序必须来自确认过的全文位置、章节与段落次序，或确实保留阅读顺序的页内位置。metadata 行顺序需要核实生成过程；chunk 编号后缀及字典序不能直接作为全文顺序。解析顺序本身也不保证 OCR 双栏读取正确。

### 第 3 步接口

```python
load_document_materials(
    tasks: Sequence[DocumentCompletionTask],
    *,
    metadata_paths: Sequence[Path],
    layer_index: ChunkLayerIndex,
) -> list[DocumentMaterials]
```

输入是同一问题经第 2 步形成的任务，以及调用方明确指定的 metadata 路径和现有层索引。每个来源路径在一次调用中读取一次，不读取 PDF，不检索、不加载模型、不清洗或截断原文。

| 输出结构 | 字段与意义 |
| --- | --- |
| `DocumentMaterials` | `task` 保留完整任务副本；`chunks` 保存原文块；`ordering_note` 说明顺序依据；`warnings` 保存输入警告及本步限制 |
| `DocumentChunk` | `document_id`、`chunk_id`、`section`、`text` 保存来源和原文；`source_metadata` 保留原始 metadata；`metadata_path` 标明读自哪个文件；`seed_evidence_ids` 标明哪些初始证据已使用该块，包含 R1 来源块 |

- 所有 source chunk 必须经调用方的层索引确认为 strict；review、excluded 或未知层级报错，不自动启用。
- 相同 chunk ID 且完整 metadata 一致时去重；同 ID 下文献、文本或其他 metadata 不一致则报错，不静默选择。
- 不同 ID 即使文本相同也保留，不在本步执行文本相似去重。
- 同章节且 `chunk_index`、`sentence_start` 有效且相互一致时，按章节内序号排列。章节之间仅保留首次遇到的展示顺序，不宣称原文顺序；位置不可靠时保留遇到顺序并记录警告。
- 原命中 metadata 缺失时保留已有 `matched_text` 和完整任务，并记录缺失。缺少 R1 来源块时保留任务中的原始 R1 文本，不编造块级切片。
- 无法确定文献编号时只保留已有命中，不猜测连接其他块。重复任务、混入其他问题、初始/R1 来源指向不同文献、命中文本冲突均报错。
- 文献任务、原有断言和输入不被修改。所有材料保持独立原文块，不拼接成伪造的连续全文。
- `full_document_order_unverified` 和 `study_attribution_not_verified` 明确表示本步没有验证全文阅读顺序和同一研究归属；不是模型给出的医学判断。

## 第 4 步：内容分类后按固定规则纳入材料

- 输入：原始问题、初始命中、同文献可用材料及辅助断言。
- 工作：程序对原文句段编号，Qwen 只按 DESIGN / METHOD / RESULT / CONCLUSION / OTHER 五类逐项分类。程序纳入前四类，OTHER 留作后备；不让模型自由选择编号，不判断回答价值或关联证明。
- 输出：补全候选材料，保留每段出处以及它属于初始命中还是同文献补充。
- 校验：每个输入编号恰好得到一个合法类别；原文及初始证据保留；无药名、对照组、阴性结果不会被程序另外排除；不生成原文没有的内容。类别不代表疗效或研究归属已验证。

使用已有 Qwen3-8B，8bit、关闭 thinking；`load_selection_runtime()` 复用核心加载器，调用方只加载一次。不使用 6.2 身份 LoRA，不做新检索、R2、OCR 修复、报告生成、问题相关性或方案归属判断。混文按本轮约定暂视作噪声：若它是方法或结果，分类后仍可能纳入，不额外建主题过滤器，也不承诺后续报告一定能消除影响。

### 第 4 步接口与规则

```python
select_document_supplements(
    materials: Sequence[DocumentMaterials],
    *,
    runtime: SelectionRuntime,
    parameters: SelectionParameters,
) -> list[DocumentSelection]
```

- `prepare_selection_passages()` 每个原文句子一个编号，无可靠句末的尾部片段原样保留并标记；不按长度切碎长句。编号在一篇材料内连续，跨 chunk 不合并；每片保存 `[start, end)` 原文坐标。
- 中英文 `。！？.!?` 及全角 `．` 为句末线索，连续句末标点及闭引号留在前句。保护剂量小数、常见英文缩写和姓名首字母；逗号、分号、冒号、OCR 换行不作句界。分句是边界启发式，不承诺恢复原论文语法或章节。
- `build_selection_messages()` 每次只传一个 chunk 的全部编号句段及章节提示。模型能看到相邻句，但不接收问题、初始命中标记、概念白名单或 6.2 断言；这些仍完整保存在程序任务中。
- 提示词 `document-content-v1` 定义五类：DESIGN 为人群/纳排/样本/分组/比较框架；METHOD 为用药实施、疗程、检查、评价标准及统计；RESULT 为实际观察结果（含定性、阴性及无显著差异）；CONCLUSION 为总结、适用条件、局限和明确治疗建议；OTHER 为一般背景、纯参考条目、作者机构、关键词等。
- 原句兼有多类时按主要内容分类，章节不作真值，不强制实验结构。每个非空 chunk 一次调用，共享 runtime；相比整篇自由选材，单次任务变窄，但调用数及总成本需要实测。
- 模型只返回 `{"labels":[{"id":"P0001","type":"METHOD"}]}`；每个编号必须恰好一类。严格 JSON，不去围栏、不修复、不重试；重复键、漏答、多答、重复编号、非法类别或额外字段拒收整篇文献结果，不把缺答自动当 OTHER。
- `SelectionOutputError` 保留失败 chunk、原始返回、token 数和此前已完成的调用记录；不返回部分补充材料。CUDA 等技术异常原样传播。
- 用实际 tokenizer 计数，完整每次聊天含系统提示词、章节、原文及模板；生成前检查所有调用预算，超限不截断，模型上下文也预留输出空间。`max_input_tokens` 和 `max_new_tokens` 是单次 chunk 调用预算，文献 token 数是多次调用合计。
- 程序按来源顺序回填原文并再次校验切片。四类纳入、OTHER 保留后备，不再加药名、分数、相关性或组别门槛；初始证据即使被分为 OTHER 也不会删除，命中的初始编号不重复添加。
- 首版不自动合并远隔原文、不建立方案结果图、不新增“研究方向已补齐”的推断。跨片段去重与最终报告预算仍属第五步。

| 输出 | 意义 |
| --- | --- |
| `task` | 完整初始任务副本，包含初始证据、来源和辅助断言 |
| `supplements` | 已选新增原文片段，含编号、chunk、坐标、初始标记和片段标记；内容不是模型生成 |
| `reserve` | 未选新增原文片段；独立保留供复核，不自动加入报告 |
| `selected_initial_ids` | 模型选中但已保留在初始证据中的编号，不重复计入新增 |
| `passage_types` | 全部编号到五类枚举的映射，便于查看、标注与后续 LoRA 数据准备 |
| `classification_calls` | 每个 chunk 的实际原始 JSON、输入及输出 token 数；不把程序组装文字冒充单次模型返回 |
| `input_token_count`、`output_token_count` | 本篇全部 chunk 调用的 token 总和，不是单次预算 |
| `prompt_version`、`warnings` | 选材提示词版本及来源/空选择/片段警告；空选择不证明文章没有有用信息 |

## 断言的辅助用法

- 补全时使用药名及引句位置作为查找线索；角色标签不决定材料是否入选。
- 报告生成输入保留原文和出处，首版不把角色标签作为判断前提。
- 后续报告核查可以将断言作为对照线索，冲突时回看原文，不以断言为裁判。
- 结果可能没有重复药名，结论可能被标为非直接相关；这些都不是丢弃材料的理由。
